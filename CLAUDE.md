# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

Invixray is a macOS menu bar app that watches the clipboard for invisible Unicode characters used in LLM prompt-injection attacks. **v0.1.0 is published** as an unsigned zip on a private GitHub Release (`snaka/invixray`).

Read **[ROADMAP.md](ROADMAP.md)** for deferred work. The detection rules trace to Graves (2026), [*Reverse CAPTCHA*](https://arxiv.org/html/2603.00164v1).

## Build & dev commands

The Xcode project is **generated from `project.yml`** by [XcodeGen](https://github.com/yonaskolb/XcodeGen) and is gitignored. Regenerate after editing `project.yml` (or pulling).

```bash
xcodegen generate
open Invixray.xcodeproj
```

Or build / test from the command line:

```bash
# pure-Swift detection module (fast)
swift test

# full app, unsigned, into ./build (gitignored)
xcodebuild -project Invixray.xcodeproj -scheme Invixray -configuration Debug \
  -derivedDataPath ./build -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY="-" CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO build
```

The Release build path used for the v0.1.0 zip:

```bash
xcodebuild -project Invixray.xcodeproj -scheme Invixray -configuration Release \
  -derivedDataPath ./build -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY="-" CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO build
ditto -c -k --sequesterRsrc --keepParent \
  build/Build/Products/Release/Invixray.app build/Invixray-vX.Y.Z.zip
```

## Layout

```
Package.swift                                # SwiftPM root: defines the two library targets
project.yml                                  # XcodeGen project definition (source of truth for the .app)
Sources/
  InvixrayCore/                              # pure-Swift, platform-independent
    Finding.swift                            # Severity, Kind, Finding struct
    InvisibleCharacterDetector.swift         # detect() + sanitize() + classifiers
  InvixrayMonitor/                           # AppKit-bound clipboard polling
    PasteboardSource.swift                   # protocol + NSPasteboardSource impl
    ClipboardMonitor.swift                   # tick() + events() AsyncStream
  Invixray/                                  # macOS app target (XcodeGen-managed)
    InvixrayApp.swift                        # @main + AppDelegate
    AppCoordinator.swift                     # wires Monitor → MenuBar + Notifications
    MenuBarController.swift                  # NSStatusBar item + NSPopover + auto-show
    NotificationManager.swift                # UNUserNotification (best-effort)
    FindingsPopoverView.swift                # SwiftUI: severity-colored banner + actions
    Info.plist / Invixray.entitlements       # generated by xcodegen — do not hand-edit
Tests/
  InvixrayCoreTests/                         # 18 tests (Swift Testing)
  InvixrayMonitorTests/                      # 6 tests with mock pasteboard
ROADMAP.md                                   # deferred work
```

## Key architecture decisions

- **Pure-Swift detection module is target-isolated** (`InvixrayCore`) so it stays unit-testable without AppKit / a pasteboard. AppKit-bound code lives in `InvixrayMonitor`; the app target glues them together.
- **Polling, not notifications.** `NSPasteboard` has no change notification — `ClipboardMonitor` polls `changeCount` on a 500 ms `Task.sleep` loop. The loop is wrapped in `events()` returning an `AsyncStream`; `tick()` is exposed separately so unit tests can drive ticks deterministically.
- **`PasteboardSource` protocol** abstracts `NSPasteboard.general` so the monitor is testable with an in-memory mock. All monitor code is `@MainActor`.
- **Auto-shown popover is the primary feedback channel**, not the system notification. Notifications via `UNUserNotificationCenter` are best-effort — unsigned dev builds and Focus modes routinely silence them. The popover always pops on detection so the user cannot miss it.
- **Sanitize removes findings by range only**, not by stripping all matching codepoints globally. The Graves paper warns that "remove all zero-width chars" breaks Indic scripts and ZWJ emoji; range-based removal sidesteps that.
- **State reset on Dismiss / Sanitize.** After the user acts, the menu bar icon returns to idle and the popover renders the "All clear" state. Otherwise the alert state would persist across benign clipboard changes (which the monitor doesn't surface).

## Conventions

- macOS 14 (Sonoma) minimum. Don't add fallbacks for earlier versions.
- Swift 6.0, Swift Testing (not XCTest) for new tests.
- Not sandboxed in v1 — `NSPasteboard` access works without it and there is no Mac App Store target.
- English in code and comments. UI strings can stay English for now.
- Default to no comments. Code should be self-explanatory; rationale lives in `ROADMAP.md` and commit messages.
- Detection rule changes must trace to a public source (e.g. the Graves paper). Don't invent ad-hoc patterns — false positives on benign Unicode are easy to introduce.

## CI

Two GitHub Actions workflows:

- `.github/workflows/build.yml` — runs on PRs and pushes to `main`; `swift test` + an unsigned compile-only check.
- `.github/workflows/release.yml` — runs on `v*` tag push (real release) or manual `workflow_dispatch` (dry-run that only uploads the DMG artifact, skipping the Release + tap bump). Full sign / notarize / staple / DMG pipeline, then pushes an updated `Casks/invixray.rb` to **`snaka/homebrew-tap`**.

See **[RELEASE.md](RELEASE.md)** for the secrets list and the operator runbook.

## Distribution

The repo is **public**. The intended channel is `brew install --cask snaka/tap/invixray` (notarized DMG via the release pipeline).

`v0.1.0` is the legacy **unsigned** zip from before the pipeline existed. The first signed release is **v0.1.1** (RELEASE.md explains why).

## Gotchas

- After `xcodegen generate`, `Sources/Invixray/Info.plist` and `Invixray.entitlements` get **populated** from `project.yml`. Don't hand-edit them — edit `project.yml` and regenerate.
- The `*.xcodeproj/` glob in `.gitignore` is intentional. Never `git add` the generated project.
- Use `ditto -c -k --sequesterRsrc --keepParent` to zip the `.app` (not `zip`); regular `zip` loses macOS extended attributes that Gatekeeper relies on.
- The `Settings { EmptyView() }` scene in `InvixrayApp.swift` exists only because the `App` protocol requires a Scene — it is never shown. The whole UI is owned by `AppDelegate` → `MenuBarController`.
- The user has `commit.gpgSign = true` and `tag.gpgSign = true` globally. Tags must be **annotated** (`git tag -a … -m …`); lightweight tags fail to sign.
